# KeySource: редизайн работы с подписками VlessPanel

Ветка: `feature/keysource-subscriptions` · Дата: 2026-08-09 · Статус: черновик (дизайнер + кодер)
Дизайн-таргет: **десктоп 27" 2K (2560×1440)**, мобильная версия не нужна (но не ломать).

## Идея

Сейчас подписка формируется копипастом client-inbound связок из панелей в поле вставки.
Новый флоу: сущность **KeySource** («источник ключа») — связка клиент@панель + инбаунд@панель, из которой извлекается vless-ключ. Под клиентом — чипсы инбаундов; клик по чипсе кладёт KeySource (зелёная чипса с именем сервера) в открытую подписку. Кнопка «Создать подписку» (активна при ≥1 чипсе) генерит файл. Синк с агрегатором — руками (кнопка/скрипт как сейчас).

## Нейминг (утверждено)

**KeySource**. Два типа:
- **panel** — panelId + clientEmail + inboundId (достаёт ключ по сети с 3X-UI)
- **manual** — хранит строку vless-ключа (старые панели без API, разовые ключи)

## Модель данных

```
KeySource {
  id: string (uuid)
  type: "panel" | "manual"
  // panel:
  panelId: string?
  clientEmail: string?
  inboundId: int?
  // manual:
  vlessLink: string?
  // общее:
  label: string?              // null = авто "{remark инбаунда}-{email}" / из #label ссылки
  cachedKey: { link, fetchedAt }?   // кеш для отображения, НЕ истина
  lastTest: { status, at }?         // результат test-single
  createdAt, updatedAt
  status: derived             // ok | expired | missing | panel_unreachable
}

SubKey { id, link, keySourceId? }    // keySourceId=null → manual/legacy
Subscription { id, name, status: "draft"|"active", keys: [SubKey], updatedAt }
```

Принципы:
- Панельный KeySource хранит **ссылку**, не ключ. Ключ извлекается при генерации (свежий) и кешируется для отображения. Частые запросы к панелям — допустимы (ключей мало).
- **Дедупликация только в пределах типа**: panel+panel — по триплету (panelId+email+inboundId); manual+manual — по vless-строке. Между типами дублей не проверяем.
- Хранилище: расширить JSON-сторадж (/data). БД не нужна (объёмы малые).

## UI-спецификация

- **Чипса KeySource**: одна строка, слева — надпись (имя сервера + remark инбаунда + email; manual — label). Справа — статус, трафик (если API отдаёт), дата окончания, результат теста демоном. Кнопка копирования ключа в буфер. Крестик удаления.
- **Статусы чипсы**: ok — зелёная; expired — **красный циферблат** (иконочка) + статус «закончился»; missing / panel_unreachable — жёлтый треугольник «!» (ключ не извлечётся).
- **Клик по чипсе** → модалка KeySource: вся инфа (сервер, инбаунд, email, expiry, трафик, последний тест) + кнопка «Скопировать vless-ключ».
- **Статус подписки**: «черновик» | «включен» — справа от подписки.
- **Manual-чипса**: серая; без трафика/enabled; тест демона — можно.
- **Кнопка «Создать подписку»**: активна при ≥1 чипсе; после создания — «Перегенерировать». Не трогает manual-чипсы.
- **Тестирование (2 этапа)**: 1) на каждом KeySource — кнопка теста (test-single); 2) после генерации — «Тест подписки» перед синком (POST /subscriptions/:id/test), в том же блоке ниже.
- **Удаление подписки**: кнопка с **модалкой подтверждения** («точно удалить?») — защита от случайного клика.
- **Создание подписки**: модалка «+ Новая подписка» сразу с именем + проверка дублей имён.
- **Статус синка**: автоопределение — сравнить Last-Modified подписки на агрегаторе (HEAD к /sub/{name}) с локальным mtime файла configs-{name}.txt. Бейдж «изменено — требуется синк» гаснет, когда агрегатор отдаёт версию не старше локальной. Синк — тот же механизм rsync.
- **Таймаут на операции с API 3X-UI: 10 секунд.** Понятные ошибки, тосты.

## Кейсы и статусы KeySource

| Статус | Когда | Генерация | UI |
|---|---|---|---|
| ok | панель отдаёт ключ, клиент активен, срок не истёк | включается | зелёная чипса |
| expired | expiryTime истёк | **не включается** + отчёт | красный циферблат, «закончился» |
| missing | клиент/инбаунд удалён на панели | пропуск + отчёт | жёлтый треугольник |
| panel_unreachable | таймаут 10с / панель недоступна | пропуск + отчёт | жёлтый треугольник |
| manual | ручной ключ | включается всегда | серая чипса |

Удаление KeySource: **без конвертации в manual**. SubKey удаляются из подписок; перед удалением — предупреждение «используется в N подписках». Если нужно сохранить — скопировать ключ в буфер и добавить manual'ом вручную.

## Трафик на чипсе

Источник: 3X-UI `/panel/api/clients/list` / `/panel/api/clients/get/{email}` (up/down из clientStats) — эндпоинт есть во всех версиях 3.3.1+ (OpenAPI сохранены в `spec/3xui/{3.3.1,3.4.2,3.5.0,3.6.0}/openapi.json`). Показывать для всех API-панелей, если API отдаёт; иначе «нет данных». Нужен новый эндпоинт VlessPanel.

## Таски дизайнеру

1. Двухпанельный экран «Подписки» (десктоп 2K): слева панели → клиенты → чипсы инбаундов; справа выбранная подписка.
2. Компонент «чипса KeySource»: зелёная, одна строка, статус-точка, красный циферблат (expired), жёлтый треугольник (missing/unreachable), справа статус/трафик/expiry/тест, копия ключа, крестик.
3. Компонент «manual-чипса» (серая).
4. Модалка деталей KeySource (по клику на чипсу): вся инфа + кнопка копирования vless-ключа.
5. Модалка «+ Новая подписка» (имя, ошибка дубля).
6. Модалка подтверждения удаления подписки.
7. Состояния кнопки «Создать подписку»/«Перегенерировать» (disabled/loading/success/error + отчёт частичного успеха).
8. Блок тестирования: на чипсе (per-key) + тест подписки перед синком.
9. Бейдж «изменено — требуется синк» (автогаснет).
10. Пустые состояния (нет панелей/клиентов, клиент без инбаундов, подписка без чипс), loading/тосты.

## Таски кодеру

Бэкенд:
1. Модель KeySource (panel/manual) + миграция JSON-хранилища; дедуп по типам.
2. API:
   - POST /api/key-sources {type, panelId?, clientEmail?, inboundId?, vlessLink?, label?}
   - GET /api/key-sources (со статусами, кешами, lastTest, трафиком)
   - DELETE /api/key-sources/:id (SubKey удаляются из подписок; предупреждение о N подписок)
   - GET /api/key-sources/:id/key (свежий из панели, кеш, force refresh)
   - GET /api/key-sources/:id/test (test-single через демон + lastTest)
   - GET /api/key-sources/:id/traffic (clientStats через /panel/api/clients/list)
3. SubKey.keySourceId nullable; Subscription.status draft|active.
4. Генерация: POST /api/subscriptions {name, keySourceIds[]} — свежие ключи, expired/missing/unreachable пропускаются + отчёт; PUT — перегенерация (manual не трогаем).
5. Таймаут 10с на операции с 3X-UI; человекочитаемые ошибки; частичный успех.
6. Статус синка: сравнение Last-Modified агрегатора (HEAD /sub/{name}) с локальным mtime файла.
7. Кеш ключей TTL + force-refresh; lastTest кеш.

Фронтенд:
8. Двухпанельный экран по дизайну; группировка клиентов по панелям.
9. Клик по чипсе инбаунда → добавление KeySource в активную подписку (нет активной → предложить создать).
10. Модалки: новая подписка, детали KeySource, подтверждение удаления подписки.
11. Кнопки «Создать подписку»/«Перегенерировать», отчёт после генерации, копирование в буфер.
12. Блоки тестов (per-key + подписка), бейдж синка, тосты, пустые состояния.

Тестирование (ручной сценарий): создание из KeySource → файл; перегенерация; недоступная панель → отчёт; legacy-подписка не ломается; expired → красный циферблат, пропуск при генерации; manual-ключи; копирование; тест per-key и подписки; удаление подписки с подтверждением; удаление KeySource из N подписок.
